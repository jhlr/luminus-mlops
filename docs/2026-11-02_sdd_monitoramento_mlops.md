# SDD: Luminus MLOps monitoring (short)

Date: 2026-11-02 | Source of truth for the design. Written in English because it doubles as an instruction file; the professor-facing docs and the README are in Brazilian Portuguese.

## 1. Goal and grading map

Observe an off-the-shelf image classifier (torchvision MobileNetV3-Small, ImageNet weights, CPU) served with BentoML. Monitoring means mainly **writing a trace of every request and response to a file**, from which histograms, boxplots, KS and PSI can be computed against a reference set. We monitor features of the input image and the model outputs, never pixels.

| Deliverable | Points | Where |
|---|---|---|
| D1 append-only JSON Lines log, with variables for histograms, boxplots, KS, PSI | 50 | `monitoring/tracing.py`, `logging_setup.py`, `features.py`, `outputs.py` |
| D2 `GET /metrics` (Prometheus) + text and spreadsheet on latency histogram, boxplot, error rate, retention | 10 | `monitoring/metrics.py`, `docs/2026-11-02_monitoramento_metrics_analysis.{md,xlsx}` |
| E1 Loki | 5 | `monitoring/alloy/config.alloy`, `docker/monitoring/compose.yml` |
| E2 endpoint that extracts the variables | 20 | `GET /data/variables` on inference and `monitor`; `/data/{reference,summary,drift}` on `monitor` |
| E3 Prometheus server | 15 | `monitoring/prometheus.yml` |

## 2. Three environments (hard requirement)

| Environment | Image / stack | Contains | Must not contain |
|---|---|---|---|
| Reference ("training": nothing is trained) | `docker/reference`, extra `reference` | torch, torchvision, scipy; builds `artifacts/reference*.csv` with the real model | BentoML, serving code path |
| Inference | `docker/inference`, extra `inference` | BentoML, torch, torchvision, log writer, `/data/variables` | pandas, scipy, mlflow, datasets, any drift analysis |
| Monitoring | `docker/monitoring`, extra `monitor` | Prometheus, Loki, Alloy, Grafana, `monitor` (BentoML + pandas + scipy) | torch, model weights |

Interfaces: the reference CSVs (`artifacts/`, read-only for monitoring); `inference:3000/metrics` scraped over the external Docker network `luminus-net`; the host directory `serving-logs/` (inference read-write; Alloy and `monitor` read-only). Each environment starts and stops alone; inference keeps logging when monitoring is down.

## 3. Decisions

1. **One owner per responsibility:** features (`features.py`), output variables (`outputs.py`), drift math and thresholds (`drift.py`), reference split (`split.py`), log parsing (`log_reader.py`), log events (`tracing.py`).
2. **Log:** `serving-logs/inference.log`, JSON Lines, `RotatingFileHandler` (50 MB, 5 backups) created lazily inside the single BentoML worker. Two lines per `/predict` call linked by `request_id`: `request` (input features, prefix `in_`) and `response` (status, `latency_ms`, outputs prefix `out_`, `error`). Invalid input that never reaches the API function gets a `response` line only. UTC ISO timestamps with microseconds.
3. **Privacy:** no pixels; `error` is exception class plus a fixed code, never the message; client IP only as a 12-char SHA-256 prefix.
4. **Input features:** L, R, G, B means and 256-bin histograms, `luminance_std`, `sharpness` (variance of the Laplacian), `width`, `height`, `file_bytes`.
5. **Output variables:** `predicted_class` (categorical), `confidence` (top-1 softmax), `margin` (top-1 minus top-2), `entropy` (bits), `top5_mass`.
6. **Drift:** KS on aggregated 256-bin histograms per channel with **equal weight per image** (each histogram normalized to sum 1 before summing); p-value from `scipy.stats.kstwobign` with n in images; levels D >= 0.05 yellow, D >= 0.10 red, INCONCLUSIVE below 8 images. PSI: 10 reference-quantile bins for numerics, 16 bins for pixel histograms, categories for categoricals, epsilon 1e-6, bands 0.10 / 0.25 (industry convention, not a proven rule). Gauges `luminus_drift_*` on the `monitor` `/metrics` over a sliding window of the last 100 images.
7. **Data:** Imagenette 320 px (fast.ai, about 340 MB). Reference = 500 train images chosen by sorting paths, shuffling with seed 0 and taking the first 500. Traffic sets: `holdout` (the other train images, no-drift control), `val` (the other split), `woof` (Imagewoof 320 px val, dogs only: natural shift). Synthetic drift `mild` and `strong` is applied by the load generator. Datasets are never committed.
8. **Load generator:** closed loop (`--concurrency`, default 1), so the single worker is never flooded; 5% invalid requests by default.
9. **Grafana:** one provisioned dashboard generated by `scripts/build_dashboards.py`; box plots use the Business Charts (ECharts) panel fed by `/data/summary` through the Infinity datasource, because core Grafana has no box plot.

## 4. Acceptance criteria (all verified, see README and docs for numbers)

1. Two lines per valid call, one for an invalid call; valid JSON; request before response; histograms sum to `width * height`.
2. `/metrics`, `/livez`, `/readyz`, `/data/*` write no log lines.
3. Privacy, append-only, rotation (against a running service) and response-contract tests pass; every guard test was seen RED before being accepted.
4. `/metrics` parses with `prometheus_client` and has BentoML's request counter and duration buckets plus the custom series.
5. Prometheus targets `inference` and `monitor` UP; Loki line count equals the lines on disk, also after rotation.
6. Every panel of the Grafana dashboard returns data after a load.
7. `mypy` strict clean and `pytest tests` green.
